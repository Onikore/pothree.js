# Тесты

## Визуальный регресс и smoke-тест примеров

Скрипт `tests/visual/run.mjs` открывает каждую страницу из `examples/` в headless-браузере
(Playwright), дожидается загрузки облака, ставит камеру в позицию из эталона, делает скриншот и
сравнивает его с эталоном (pixelmatch). Попутно собирает ошибки и предупреждения консоли.

```
node tests/visual/run.mjs                      сравнить с эталоном (exit 1, если что-то упало)
node tests/visual/run.mjs --update             снять эталон заново
node tests/visual/run.mjs --only lion,copc     только указанные примеры
node tests/visual/run.mjs --group formats      smoke-тест форматов (группа из config.json)
node tests/visual/run.mjs --browser firefox    другой браузер (chromium | firefox | webkit)
node tests/visual/run.mjs --jobs 2             сколько примеров гонять параллельно (по умолчанию 4)
```

Каждый поток — браузер с программной отрисовкой на CPU, это сильно грузит процессор. На ноутбуке
`--jobs 2` и не запускать два прогона одновременно.

### Как определяется «облако загрузилось»

Каждые 250 мс скрипт читает `Potree.numNodesLoading`, число видимых точек и число видимых узлов
сцены. Состояние считается стабильным, если узлы не грузятся, а точки и узлы не менялись
2 секунды **и** 30 отрисованных кадров подряд. Кадры важны: Potree переносит в сцену не больше
2 загруженных узлов за кадр, а под SwiftShader кадр может идти секунду. Предел — 180 секунд на пример. Вьюер ищется как `window.viewer` или `window.potreeViewer`, в том числе внутри iframe
(`embedded_iframe`).

### Камера

При `--update` скрипт записывает положение камеры (`position` и точку взгляда) в
`baseline.json`. При сравнении ставит камеру туда же и снова ждёт загрузки. Поэтому сравнение
не зависит от того, как пример сам выставляет камеру.

### Детерминизм

Chromium запускается с программным WebGL (SwiftShader: `--use-angle=swiftshader
--enable-unsafe-swiftshader`), окно 1280×800, `deviceScaleFactor` 1. Два прогона на одном коде
дают diff 0,00%. Эталон и проверка должны сниматься одной версией Playwright и браузера
(закреплены в `package.json`: `playwright` 1.64.0, chromium 156).

### Критерии провала

- доля отличающихся пикселей больше `maxDiff` (по умолчанию 0,5%; порог цвета pixelmatch 0,1);
- облако должно быть, а видимых точек 0;
- появились ошибки страницы (`pageerror`), которых не было в эталоне;
- пример не загрузился за 180 секунд.

Предупреждения консоли не валят тест, но сохраняются в `report.json` для сравнения с эталоном.

### Файлы

| Путь | Что |
|---|---|
| `tests/visual/run.mjs` | скрипт |

| `tests/visual/baseline/<пример>.png` | эталонные скриншоты (сняты на исходном коде, three r124) |

### Сетевые данные

Многие примеры берут облака с внешних серверов (`5.9.65.151`, `potree.org`, Arena4D, тайлы Cesium).
Если сервер недоступен, пример упадёт по таймауту. Это не регресс кода — смотрите `problems` в
`report.json`. Для примеров с тайлами карты Cesium и анимацией допуск увеличен до 5%.

## Smoke-тест форматов

Группа `formats` в `config.json`: примеры, каждый из которых грузит свой формат.

| Пример | Формат | Данные |
|---|---|---|
| `lion` | Potree 1.x, бинарные узлы | `pointclouds/lion_takanawa` |
| `lion_las` | Potree 1.x, узлы LAS | `pointclouds/lion_takanawa_las` |
| `lion_laz` | Potree 1.x, узлы LAZ | `pointclouds/lion_takanawa_laz` |
| `ept`, `ept_binary`, `ept_laz_14`, `ept_zstandard` | EPT: laszip, binary, LAZ 1.4, zstandard | `pointclouds/lion_takanawa_ept_*` |
| `copc` | COPC | `pointclouds/lion_takanawa.copc.laz` |
| `potree2` | Potree 2.0, без сжатия | `pointclouds/lion_takanawa_potree2` |
| `potree2_brotli` | Potree 2.0, Brotli | `pointclouds/lion_takanawa_potree2_brotli` |

Данные Potree 2.0 сделаны из `lion_takanawa.copc.laz` конвертером PotreeConverter 2.1.1 (команды —
`pointclouds/lion_takanawa_potree2/README.md`). Примеры `vr_*` тоже грузят Potree 2.0, но с
potree.org, который запрещает чужим сайтам загрузку (CORS), поэтому они пропускаются.

COPC читает файл кусками (HTTP `Range`), поэтому тестовый сервер поддерживает `Range`.

## Пропущенные и особые примеры

| Пример | Почему |
|---|---|
| `vr_*` | данные на potree.org закрыты CORS — работают только на самом potree.org |
| `arena4d` | сервер тестовых данных Arena4D отвечает 503 |
| `light_animated`, `light_ca13`, `camera_animation` | анимация никогда не останавливается: режим `animated` — ждём только окончания загрузки, допуск 10%; ловим падения и пустой кадр |

## Тест выбора точек (picking)

`tests/visual/pick.mjs` открывает `lion`, `potree2`, `ept`, `copc`, `classifications`, ставит камеру
из эталона, выбирает точки по сетке 5×5 позиций экрана (включая полосу у краёв) через
`Potree.Utils.getMousePointCloudIntersection` — тот же вызов, что у инструментов измерения — и
сравнивает координаты выбранных точек с эталоном (`tests/visual/baseline/pick.json`, допуск 0,001).

Эталон сначала был снят на исходном коде, и вплоть до three r152 форк совпадал с ним точно (кроме
краёв, см. ниже). С three r163 буфер глубины render target по умолчанию 24-битный вместо 16-битного
(как в оригинале на WebGL1), и при близких по глубине точках picking выбирает действительно ближайшую;
в 4 из 125 позиций это другая соседняя точка (сдвиг от 5 мм до 1,5 единицы). Причина доказана опытом:
с 16-битной глубиной (`DepthTexture(…, UnsignedShortType)`) результат снова совпадает с оригиналом
точно. Эталон переснят на форке (r163); эталон оригинала — в истории git (коммит до этого изменения).

```
node tests/visual/pick.mjs              сравнить
node tests/visual/pick.mjs --update     снять эталон (на исходном коде)
```

Исключение: у краёв области отрисовки (ближе 33 px) оригинал выбирал неправильно — промахивался или
брал точку у середины сдвинутого окна, а не у курсора (см. `CHANGELOG.md`). Там расхождения с эталоном
не считаются ошибкой; в остальной части экрана требуется точное совпадение.

Важно для всех тестовых серверов: `potree.css` должен отдаваться с `Content-Type: text/css`,
иначе браузер не применяет стили и область отрисовки получается высотой 20 px.

## Рендер по требованию

`node tests/visual/ondemand.mjs` — `lion` с `viewer.renderOnDemand = true`: после загрузки
`Potree.framenumber` перестаёт расти; кадр в простое совпадает с кадром непрерывной отрисовки
(значит, ничего не осталось недорисованным); колесо мыши и смена `scene.view` из кода снова
запускают отрисовку. Эталона нет, выход 1 при ошибке.

## Операции

`node tests/visual/operations.mjs [--only lion]` — lion, potree2, ept, copc: выборка в боксе равна
перебору всех загруженных точек, выделение/скрытие видны, отмена возвращает картинку пиксель в
пиксель, классификация пишется и откатывается, `toJSON`/`fromJSON`, правки переживают
выгрузку/загрузку узлов, кнопка «Select in volumes» и Ctrl+Z. Подробно — `docs/operations.md`.

## Намеренные отличия от оригинала в визуальном тесте

`config.json`: `ignore: [[x, y, w, h], ...]` — прямоугольники, которые не сравниваются (в обоих
снимках зануляются). Сейчас: сайдбар ниже блока Clipping (300 × 395 px слева) в 10 примерах с
раскрытым меню Tools — в нём новый блок Selection сдвигает всё ниже; в `embedded_iframe` — тот же
участок внутри iframe. Облако в этих примерах сравнивается как прежде.
